## 1. 这段代码负责什么

支付对接只做三件事：

```
① 用商户私钥 + 支付宝公钥，构造一个可用的 AlipayClient
② 提交「电脑网站支付」请求，让支付宝生成收银台表单
③ 把表单 HTML 返回前端，浏览器自动跳转到支付宝
```

**它不负责：**

| 不负责 | 归谁 |
|---|---|
| 判断用户是否付款成功 | 支付回调（异步通知） |
| 更新订单为 `PAY_SUCCESS` | 支付回调 / 补偿任务 |
| 发货、充值、返利 | 业务事件监听 |
| 订单超时关闭 | 定时任务 |

一句话：**支付对接 = 「把订单交给支付宝」，付款结果必须靠回调来确认，绝不能靠前端。**

## 2. 完整时序

```
前端                 AliPayController      OrderServiceImpl      支付宝网关          用户浏览器
 │                        │                       │                   │                  │
 │ POST create_pay_order  │                       │                   │                  │
 │───────────────────────>│ createOrder           │                   │                  │
 │                        │──────────────────────>│                   │                  │
 │                        │                       │ pageExecute       │                  │
 │                        │                       │──────────────────>│                  │
 │                        │                       │<── form HTML ─────│                  │
 │                        │                       │ 回写 pay_url      │                  │
 │<── data = form HTML ───│                       │                   │                  │
 │                                                                                        │
 │ document.write(form) ──────────────────────────────────────────────────────────────────>│
 │                                          浏览器自动提交表单                            │
 │                                                              ┌─────────────────────────┘
 │                                                              ▼
 │                                                    支付宝收银台（用户扫码/登录付款）
 │                                                              │
 │                                              ┌───────────────┴───────────────┐
 │                                              ▼                               ▼
 │                                   同步跳转 return_url              异步通知 notify_url
 │                                   （浏览器，仅展示）                （服务器，唯一可信）
```

**两条回路的职责必须分清：**

| 回路 | 谁发起 | 到达哪里 | 可信度 |
|---|---|---|---|
| `return_url` | 用户浏览器 | 前端页面 | ❌ 仅用于展示「支付完成」，**不能据此改订单** |
| `notify_url` | 支付宝服务器 | 后端接口 | ✅ 验签通过后才是支付成功的唯一依据 |

## 4. 从 0 到 1：七个步骤

### 第 1 步｜开通沙箱并签约产品

1. 打开支付宝开放平台沙箱：`https://open.alipay.com/develop/sandbox/app`
2. 拿到 **APPID**（沙箱应用 ID）。
3. 在「产品绑定」里确认已签约 **电脑网站支付**（`FAST_INSTANT_TRADE_PAY`）。未签约会报 `40004`。
4. 在「沙箱账号」里拿到**买家账号 / 卖家账号**（虚拟账号，用于登录沙箱收银台付款）。

### 第 2 步｜生成 RSA2 密钥对

支付宝要求 **RSA2（SHA256WithRSA）**：

| 密钥 | 谁持有 | 用途 |
|---|---|---|
| **应用私钥** (PKCS8) | 你 | **签名**请求，绝不可泄露 |
| **应用公钥** | 上传到支付宝 | 让支付宝校验你的签名 |
| **支付宝公钥** | 支付宝提供 | 让你**验签**支付宝的回调 |

生成方式二选一：

- 使用支付宝官方「密钥生成工具」（推荐，Windows/Mac 都有）；
- 命令行：`openssl genrsa -out app_private_key.pem 2048`，再转 PKCS8。

⚠️ **最容易踩的坑**：配置里的 `alipay_public_key` 必须是「**支付宝公钥**」，不是你自己的应用公钥。用错了会一直 `invalid-signature`。

### 第 3 步｜引入 SDK

```xml
<dependency>
    <groupId>com.alipay.sdk</groupId>
    <artifactId>alipay-sdk-java</artifactId>
    <version>4.38.157.ALL</version>
</dependency>
```

### 第 4 步｜写配置项

[`application-dev.yml`](../s-pay-mall-web/src/main/resources/application-dev.yml#L42-L50)：

```yaml
alipay:
  enabled: true
  app_id: 9021000132689924
  merchant_private_key: MIIEvQIBADAN...   # 应用私钥（PKCS8，单行）
  alipay_public_key: MIIBIjANBgkq...      # 支付宝公钥
  notify_url: http://xfg-studio.natapp1.cc/api/v1/alipay/alipay_notify_url
  return_url: https://gaga.plus
  gatewayUrl: https://openapi-sandbox.dl.alipaydev.com/gateway.do
```

| 配置项 | 说明 |
|---|---|
| `app_id` | 沙箱/正式环境的应用 ID |
| `merchant_private_key` | 应用私钥，**不能提交到 Git** |
| `alipay_public_key` | 支付宝公钥，用于验证回调签名 |
| `notify_url` | 异步通知地址，必须**公网可访问**，且不能带自定义参数 |
| `return_url` | 同步跳转地址，同上 |
| `gatewayUrl` | 沙箱网关 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`；正式环境为 `https://openapi.alipay.com/gateway.do` |

### 第 5 步｜绑定配置属性

[`AliPayConfigProperties`](../s-pay-mall-web/src/main/java/cn/bugstack/config/AliPayConfigProperties.java)：

```java
@Data
@ConfigurationProperties(prefix = "alipay", ignoreInvalidFields = true)
public class AliPayConfigProperties {
    private String app_id;
    private String merchant_private_key;
    private String alipay_public_key;
    private String notify_url;
    private String return_url;
    private String gatewayUrl;
    private String sign_type = "RSA2";   // 默认值
    private String charset = "utf-8";
    private String format = "json";
}
```

三个细节：

- `prefix = "alipay"` 对应 yml 顶层键；
- `ignoreInvalidFields = true` 允许 `enabled` 这类未声明的字段存在而不报错；
- `@ConfigurationProperties` 需要 `@EnableConfigurationProperties` 或 `@ConfigurationPropertiesScan` 才会生效。

### 第 6 步｜装配 `AlipayClient`

[`AliPayConfig`](../s-pay-mall-web/src/main/java/cn/bugstack/config/AliPayConfig.java)：

```java
@Configuration
@EnableConfigurationProperties(AliPayConfigProperties.class)
public class AliPayConfig {

    @Bean("alipayClient")
    public AlipayClient alipayClient(AliPayConfigProperties properties) {
        return new DefaultAlipayClient(
                properties.getGatewayUrl(),
                properties.getApp_id(),
                properties.getMerchant_private_key(),
                properties.getFormat(),        // "json"
                properties.getCharset(),       // "utf-8"
                properties.getAlipay_public_key(),
                properties.getSign_type());    // "RSA2"
    }
}
```

`DefaultAlipayClient` 七个参数的顺序不能错：

```
网关地址 → APPID → 应用私钥 → 传输格式 → 字符集 → 支付宝公钥 → 签名算法
```

`AlipayClient` 内部会：**签名**（用应用私钥）→ 发 HTTP → **验签**（用支付宝公钥）→ 返回响应对象。

### 第 7 步｜创建支付单

[`doPrepayOrder`](../s-pay-mall-service/src/main/java/cn/bugstack/service/impl/OrderServiceImpl.java#L122-L144)：

```java
AlipayTradePagePayRequest request = new AlipayTradePagePayRequest();
request.setNotifyUrl(notifyUrl);     // 异步通知地址
request.setReturnUrl(returnUrl);     // 同步跳转地址

JSONObject bizContent = new JSONObject();
bizContent.put("out_trade_no", orderId);          // 商户订单号，必须唯一
bizContent.put("total_amount", totalAmount.toString());  // 单位：元
bizContent.put("subject", productName);           // 订单标题
bizContent.put("product_code", "FAST_INSTANT_TRADE_PAY"); // 电脑网站支付
request.setBizContent(bizContent.toString());

String form = alipayClient.pageExecute(request).getBody();  // ← 关键

PayOrder payOrder = new PayOrder();
payOrder.setOrderId(orderId);
payOrder.setPayUrl(form);
payOrder.setStatus(PAY_WAIT.getCode());
orderDao.updateOrderPayInfo(payOrder);
```

**`pageExecute` 与 `execute` 的区别：**

| 方法 | 返回 | 用途 |
|---|---|---|
| `pageExecute(request)` | `AlipayTradePagePayResponse`，`.getBody()` 是 **HTML 表单** | 电脑网站支付：需要跳转收银台 |
| `execute(request)` | 直接返回业务响应（JSON） | 查询、退款、关单等**服务端接口** |

⚠️ 不要对 `AlipayTradePagePayRequest` 用 `execute()`，那样只能拿到参数，拿不到可跳转的表单。

## 5. 支付请求参数详解

`bizContent` 常用字段：

| 字段 | 必填 | 示例 | 说明 |
|---|---|---|---|
| `out_trade_no` | ✅ | `8256182736459182` | 商户订单号，**全局唯一**，回调时原样返回 |
| `total_amount` | ✅ | `1.68` | 金额（元），字符串，最多两位小数 |
| `subject` | ✅ | `测试商品` | 订单标题，收银台展示 |
| `product_code` | ✅ | `FAST_INSTANT_TRADE_PAY` | 电脑网站支付固定值 |
| `body` | ❌ | `商品描述` | 订单描述 |
| `timeout_express` | ❌ | `30m` | 超时时间（如 `90m`），超时后不可支付 |
| `passback_params` | ❌ | `merchantBizType=1` | 回传参数，回调时原样带回 |

**金额规则（必须记牢）：**

- 单位是**元**，不是分；
- 字符串形式，两位小数；
- 必须与订单金额**完全一致**，回调时会带回来做校验；
- 不能用 `double` 计算。

## 6. `notify_url` 与 `return_url`

| 对比项 | `notify_url`（异步） | `return_url`（同步） |
|---|---|---|
| 谁发起 | 支付宝**服务器** | 用户**浏览器** |
| 方向 | 服务器 → 服务器 | 支付宝 → 浏览器 → 前端页面 |
| 内容 | `application/x-www-form-urlencoded` 参数 | URL 查询参数 |
| 可信度 | ✅ 验签后可信 | ❌ 可被伪造/篡改 |
| 用途 | **唯一**的支付成功依据 | 页面提示「支付完成，正在跳转」 |
| 断网影响 | 会重试（8 次，约 25 小时） | 用户关了浏览器就收不到 |
| 是否必须在公网 | ✅ | ✅ |
| 能否带自定义参数 | ❌ 不能带 `?a=1` | ❌ 同理 |

**正确做法：**

```
return_url 只负责展示「支付处理中」
真正改订单 → 只在 notify_url 里做（且必须验签）
```

**配置位置**：`request.setNotifyUrl(...)` / `request.setReturnUrl(...)`，也可以用支付宝后台的默认配置，但**请求里的设置优先**。

## 7. 前端如何消费 `pay_url`

后端返回的 `data` 不是 URL，而是一段类似这样的 HTML：

```html
<form id="alipaysubmit" name="alipaysubmit" action="https://openapi-sandbox.dl.alipaydev.com/gateway.do?..." method="POST">
  <input type="hidden" name="app_id" value="9021..."/>
  <input type="hidden" name="method" value="alipay.trade.page.pay"/>
  <input type="hidden" name="biz_content" value="{...}"/>
  <input type="hidden" name="sign" value="..."/>
  <input type="hidden" name="sign_type" value="RSA2"/>
  <script>document.forms['alipaysubmit'].submit();</script>
</form>
```

所以前端三种用法：

```javascript
// 方式一：直接写入当前页面（最常见）
const res = await fetch('/api/v1/alipay/create_pay_order', {...}).then(r => r.json());
document.write(res.data);

// 方式二：新开窗口
const w = window.open('', '_blank');
w.document.write(res.data);

// 方式三：React/Vue 中插入容器
containerRef.current.innerHTML = res.data;
// 注意：innerHTML 不会执行 <script>，需手动提取并提交表单
```

**方式三的坑**：浏览器不会执行 `innerHTML` 插入的 `<script>`，表单不会自动提交。需要改为 `document.write` 或手动 `form.submit()`。

## 8. 六个技术点

**① 为什么必须用 RSA2 而不是 RSA1？**
RSA1（SHA1）已被支付宝逐步淘汰，沙箱默认要求 `RSA2`。配置里 `sign_type: RSA2` 必须与密钥类型匹配。

**② 应用私钥和支付宝公钥分别干什么？**
- 应用私钥：**我方签名**（证明请求是我发的）；
- 支付宝公钥：**我方验签**（证明回调是支付宝发的）。

这两件事方向相反，不能混用。

**③ 为什么 `pageExecute` 返回 HTML，而不是 JSON？**
电脑网站支付的本质是「浏览器表单 POST 跳转」。SDK 帮你拼好表单+自动提交脚本，浏览器执行后才能进入收银台。这是**页面跳转型**支付，区别于扫码支付/APP 支付。

**④ 为什么 `notify_url` 不能带参数？**
支付宝校验通知地址时要求是纯 URL，带 `?` 会被判为非法（`40002`）。需要携带业务信息时用 `passback_params`。

**⑤ 为什么金额要以字符串传？**
支付宝接口对金额精度敏感，`double` 序列化可能变成 `1.6800000000000002`，导致验签或金额校验失败。用 `BigDecimal.toString()` 最稳。

**⑥ 为什么沙箱能跑通，正式环境却不行？**
三处高频差异：`gatewayUrl`、`app_id`、密钥对；另外正式环境需要真实签约产品、配置应用网关/IP 白名单。沙箱买家账号也无法用于正式环境。

## 9. 常见错误排查表

| 现象 / 错误码 | 常见原因 | 排查 |
|---|---|---|
| `invalid-signature` | 私钥/公钥配对错误；用了「应用公钥」当「支付宝公钥」 | 重新生成并上传应用公钥，仔细核对配置 |
| `40002` 参数错误 | `bizContent` 缺字段 / 金额格式不对 / notify_url 带参数 | 逐字段对照文档 |
| `40004` 业务处理失败 | 产品未签约（电脑网站支付） | 沙箱应用「产品绑定」中签约 |
| `40006` 权限不足 | 应用未上线/未授权 | 检查应用状态与产品权限 |
| `isv.invalid-app-id` | appid 与网关环境不匹配 | 沙箱 appid 只能配沙箱网关 |
| 返回表单但页面空白 | 前端用 `innerHTML` 插入，`<script>` 未执行 | 改用 `document.write` 或手动 submit |
| 跳转后提示「订单已存在」 | `out_trade_no` 重复 | 保证订单号唯一（当前用随机 16 位） |
| 支付成功但订单未变 | 回调地址不通 / 未验签通过 / 返回内容不是 `success` | 见《支付回调处理全流程》 |

## 10. 安全注意与现有问题

### 必须遵守

1. **私钥只放服务端**，不进 Git、不打印日志、不下发前端。
2. **只信 `notify_url`**，永不根据 `return_url` 或前端轮询结果改订单。
3. **回调必须验签**，并校验 `app_id`、`seller_id`、`total_amount`。
4. **金额以库中订单为准**，不信任回调里的金额直接入账（应比对一致）。

### 当前实现的问题

| # | 问题 | 位置 | 风险 |
|---|---|---|---|
| 1 | 私钥、公钥明文写在 yml 并提交仓库 | `application-dev.yml` | 🔴 高：应用私钥泄露 = 可伪造支付请求 |
| 2 | 未配置 HTTP 超时 | `AlipayClient` 默认配置 | 🟠 中：网关抖动会拖死下单线程 |
| 3 | `pay_url` 字段 `varchar(2014)` 可能截断 | 表结构 | 🟠 中：表单 HTML 超长导致无法跳转 |
| 4 | 未设置 `timeout_express` | `doPrepayOrder` | 🟡 低：支付单无过期时间，依赖本地关单任务 |
