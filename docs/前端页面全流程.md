## 1. 前端构成

前端没有工程化构建，只有三个静态 HTML，由 Nginx 直接托管：

| 文件 | 路由 | 作用 | 是否参与运行 |
|---|---|---|---|
| `login.html` | `/login.html` | 展示微信二维码、轮询登录结果 | ✅ |
| `index.html` | `/index.html` | 商品展示、点击下单、跳转支付宝 | ✅ |
| `form.html` | `/form.html` | 支付宝返回表单的静态样本 | ❌ 仅用于对照排查 |
| `images/placeholder.png` | — | 二维码占位图 | ✅ |
| `images/sku-keyboard-001.png` | — | 商品图 | ✅ |

目录：[`docs/dev-ops/nginx/html`](../docs/dev-ops/nginx/html)

**技术特征：**

- 原生 `fetch`，无 axios / jQuery；
- 无框架、无构建，改完刷新即可；
- 状态存 Cookie，没有 localStorage / sessionStorage；
- 前后端完全分离，所有数据接口返回 JSON。

## 2. `login.html`：扫码登录

### 2.1 页面结构

```
┌──────────────────────────────┐
│   S Pay Mall 商城登录页       │
│                              │
│      ┌──────────────┐        │
│      │   二维码图片   │        │  ← src 指向微信 showqrcode
│      └──────────────┘        │
│                              │
│   请使用微信扫描二维码登录      │
└──────────────────────────────┘
```

### 2.2 完整流程

```
DOMContentLoaded
   │
   ├─① GET /api/v1/login/weixin_qrcode_ticket
   │      → data.data = ticket
   │
   ├─② img.src = https://mp.weixin.qq.com/cgi-bin/showqrcode?ticket=xxx
   │
   ├─③ setInterval(3s) 轮询 GET /api/v1/login/check_login?ticket=xxx
   │      │
   │      ├─ code != "0000" → 继续轮询（打印 login wait）
   │      └─ code == "0000" → clearInterval
   │                          setCookie("loginToken", openid, 30)
   │                          location.href = "index.html"
   │
   └─ 用户扫码 → 微信 POST 回调 → 后端写入 openid 缓存（本页无感知）
```

### 2.3 关键代码解读

**① 获取 ticket**

```javascript
fetch('http://192.168.1.106:8080/api/v1/login/weixin_qrcode_ticket')
    .then(response => response.json())
    .then(data => {
        if (data.code === "0000") {
            const ticket = data.data;
            // ...
        }
    });
```

- 没有请求体，是一个纯 GET；
- 后端返回 `Response<String>`，`data` 就是 ticket；
- ticket 的有效期由微信控制（代码里申请的是 30 天）。

**② 展示二维码**

```javascript
document.getElementById('qr-code-img').src =
    `https://mp.weixin.qq.com/cgi-bin/showqrcode?ticket=${ticket}`;
```

这里**不是让后端返回图片**，而是前端直接向微信请求图片。好处：

- 后端不承担二维码图片的流量与缓存；
- ticket 本身就是二维码内容的凭证，微信认识它。

**③ 轮询登录结果**

```javascript
const intervalId = setInterval(() => {
    checkLoginStatus(ticket, intervalId);
}, 3000);
```

```javascript
function checkLoginStatus(ticket, intervalId) {
    fetch(`http://192.168.1.106:8080/api/v1/login/check_login?ticket=${ticket}`)
        .then(response => response.json())
        .then(data => {
            if (data.code === "0000") {
                clearInterval(intervalId);
                setCookie('loginToken', data.data, 30);
                window.location.href = 'index.html';
            } else {
                console.info("login wait");
            }
        });
}
```

**为什么用轮询而不是 WebSocket？**
扫码是「低频、一次性、弱实时」场景，3 秒延迟用户完全无感。轮询实现成本最低，且不占长连接。生产也可换成 SSE 或长轮询。

**④ 写 Cookie**

```javascript
function setCookie(name, value, days) {
    const date = new Date();
    date.setTime(date.getTime() + days * 24 * 60 * 60 * 1000);
    document.cookie = `${name}=${value};expires=${date.toUTCString()};path=/`;
}
```

这里 `value` 是后端返回的 **openid 明文**，有效期 30 天。

### 2.4 它依赖的后端接口

| 接口 | 后端类 | 后端做了什么 |
|---|---|---|
| `GET /api/v1/login/weixin_qrcode_ticket` | `LoginController#weixinQrCodeTicket` | 取 access_token（缓存 2h）→ 调微信创建二维码 → 返回 ticket |
| `GET /api/v1/login/check_login?ticket=` | `LoginController#checkLogin` | 读 `openidToken` 缓存（1h），有值返回 openid |

**页面上看不到的环节**：用户扫码后，微信是**主动 POST** 到后端回调地址把 openid 写进缓存的。前端只是在「等」这个结果，它和微信之间没有任何直接通信。

## 3. `index.html`：商品下单

### 3.1 页面结构

```
┌──────────────────────────────┐
│  ┌────────────────────────┐  │
│  │ 美女程序员 - 同款机械键盘 │  │
│  │      [商品图片]          │  │
│  │      价格：¥1.68         │  │
│  └────────────────────────┘  │
│                              │
│  [ 立即下单「沙箱支付」 ]      │
│                              │
│  测试账号：kvhmoj3832@...     │
│  密码：111111 支付：111111    │
└──────────────────────────────┘
```

商品信息与价格**全部写死在 HTML 里**，后端 `ProductRPC` 也是 mock。这个页面只验证「下单 → 支付」链路，不验证商品系统。

### 3.2 完整流程

```
点击「立即下单」
   │
   ├─① getCookie("loginToken")
   │      ├─ 为空 → location.href = "login.html"（前端路由守卫）
   │      └─ 有值 → userId = openid
   │
   ├─② POST /api/v1/alipay/create_pay_order
   │      body: { userId, productId: "100010090091" }
   │
   ├─③ 收到 { code:"0000", data: "<form>...</form><script>...</script>" }
   │
   ├─④ document.body.innerHTML += formHtml
   │
   └─⑤ document.forms[0].submit()   ← 手动提交，跳转支付宝
```

### 3.3 关键代码解读

**① 读取登录态并做守卫**

```javascript
function getCookie(name) {
    let cookieArr = document.cookie.split(";");
    for (let i = 0; i < cookieArr.length; i++) {
        let cookiePair = cookieArr[i].split("=");
        if (name == cookiePair[0].trim()) {
            return decodeURIComponent(cookiePair[1]);
        }
    }
    return null;
}

var userId = getCookie("loginToken");
if (!userId) {
    window.location.href = "login.html";
    return;
}
```

`document.cookie` 返回的是 `"k1=v1; k2=v2"` 形式，需要拆分。注意 `name == cookiePair[0].trim()` 用 `==` 而非 `===`，属小瑕疵。

**② 下单**

```javascript
var productId = "100010090091";
var requestBody = { userId: userId, productId: productId };

fetch('http://192.168.1.106:8080/api/v1/alipay/create_pay_order', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(requestBody)
})
```

**③ 消费返回的表单 HTML**

```javascript
.then(json => {
    if (json.code === "0000") {
        var formHtml = json.data;
        document.body.innerHTML += formHtml;
        document.forms[0].submit();
    } else {
        console.error('Error:', json.info);
    }
});
```

**这三个动作是整个前端最关键的地方：**

| 动作 | 为什么 |
|---|---|
| `json.data` 是 HTML 而非 URL | 支付宝电脑网站支付返回的是「自动提交表单」 |
| `innerHTML +=` | 把表单节点插入文档 |
| `document.forms[0].submit()` | 浏览器**不会执行** `innerHTML` 插入的 `<script>`，自动提交失效，必须手动触发 |

**如果只做 `innerHTML +=` 不做 `submit()`**：页面上多了一个隐藏表单，什么也不会发生。

**如果用了 `document.write(formHtml)`**：也可以，`document.write` 会执行其中的脚本。但会清空当前文档。

### 3.4 它依赖的后端接口

| 接口 | 后端类 | 后端做了什么 |
|---|---|---|
| `POST /api/v1/alipay/create_pay_order` | `AliPayController#createPayOrder` | 查/建订单 → 调支付宝 `pageExecute` → 回写 `pay_url` → 返回表单 HTML |

### 3.5 支付完成后

代码里**没有处理支付结果**。因为：

- 支付宝同步跳转 `return_url` 指向的是 `https://gaga.plus`，不是本页面；
- 真正的支付成功由支付宝**异步通知**后端，前端不参与。

这是正确的设计：**前端不做支付结果判定。**

## 4. `form.html`：支付宝表单样本

这个文件不参与运行，是 `pageExecute` 返回值的静态样本：

```html
<form name="punchout_form" method="post"
      action="https://openapi-sandbox.dl.alipaydev.com/gateway.do?...">
    <input type="hidden" name="biz_content"
           value="{&quot;out_trade_no&quot;:&quot;2104794633863934&quot;,...}">
    <input type="submit" value="立即支付" style="display:none">
</form>
<script>document.forms[0].submit();</script>
```

**能读出四件事：**

| 观察 | 含义 |
|---|---|
| `action` 是网关地址 + 一堆 query | 签名、app_id、notify_url、return_url 都在 URL 上 |
| `biz_content` 被 HTML 转义 | JSON 里的 `"` 变成 `&quot;` |
| `submit` 按钮 `display:none` | 用户不需要点，脚本自动提交 |
| 末尾有 `<script>` | 说明必须执行脚本才会跳转 |

排查时可以拿它和接口实际返回做对比。

## 5. Cookie 登录态机制

### 5.1 现状

```
写入：login.html  setCookie('loginToken', openid, 30)
读取：index.html  getCookie('loginToken') → userId
```

| 属性 | 当前值 | 评价 |
|---|---|---|
| 名字 | `loginToken` | 名为 token，实际存的是 openid |
| 值 | openid 明文 | 🔴 泄露即可冒充 |
| 有效期 | 30 天 | 🔴 过长 |
| `HttpOnly` | 未设置 | 🔴 JS 可读，XSS 可窃取 |
| `Secure` | 未设置 | 🔴 HTTP 下也会发送 |
| `SameSite` | 未设置 | 🟠 存在 CSRF 风险 |
| `Path` | `/` | 合理 |

### 5.2 为什么这是个危险设计

openid 是「用户在该公众号下的唯一标识」。一旦拿到它：

- 可以直接调 `create_pay_order`，以该用户身份下单；
- 后端**完全不校验**这个 userId 的真实性（没有 token 校验、没有签名）。

也就是说，**Cookie 里的 openid 就是一张永不过期、可伪造的身份证。**

### 5.3 正确做法

```
登录成功
  → 后端签发短期 JWT（含 userId，2h）+ refreshToken
  → Set-Cookie: token=xxx; HttpOnly; Secure; SameSite=Lax; Path=/
  → 前端不再自己拼 userId，请求带 Cookie 即可
后端
  → 拦截器解析 JWT → 得到 userId → 放入 ThreadLocal
  → Controller 从上下文取 userId，忽略请求体里的同名字段
```

关键点：**openid 绝不出现在前端可读的位置。**

## 6. 页面与接口的完整映射

```
login.html
 ├─ GET  /api/v1/login/weixin_qrcode_ticket   → ticket
 ├─ GET  https://mp.weixin.qq.com/cgi-bin/showqrcode?ticket=   （直连微信）
 └─ GET  /api/v1/login/check_login?ticket=    → openid
        │
        └─ setCookie(loginToken=openid, 30d) → 跳转
                     │
                     ▼
index.html
 ├─ GET  Cookie loginToken                     （纯前端）
 └─ POST /api/v1/alipay/create_pay_order       → 表单 HTML
        │
        └─ POST 表单到支付宝网关 → 收银台
                     │
        用户付款 ────┘
                     │
                     ▼
        支付宝 → 后端 notify_url（前端无感知）
```

**前端只负责两件事：拿身份、发起支付。** 所有状态判定都在后端。

## 7. 七个前端问题

| # | 问题 | 位置 | 风险 | 说明 |
|---|---|---|---|---|
| 1 | Cookie 存 openid 明文、30 天、无 HttpOnly | `login.html#L96-L101` | 🔴 高 | XSS 一行代码即可窃取，且无过期约束 |
| 2 | userId 由前端传入 | `index.html#L87` | 🔴 高 | 改 Cookie 就能替他人下单 |
| 3 | 接口地址硬编码 `192.168.1.106:8080` | `login.html#L55`、`index.html#L94` | 🟠 中 | 换机器/部署即失效，且绕过 Nginx 导致跨域 |
| 4 | 轮询无上限、无超时 | `login.html#L64-L66` | 🟠 中 | 页面开着就一直请求，二维码过期也不重取 |
| 5 | `document.forms[0].submit()` 依赖顺序 | `index.html#L113` | 🟠 中 | 页面若新增其他 `<form>` 会提交错表单 |
| 6 | `innerHTML +=` 重建整个 body | `index.html#L112` | 🟡 低 | 重绘开销大，原有事件监听可能丢失 |
| 7 | 无 loading、无防重复点击 | `index.html#L86` | 🟡 低 | 连点会发多次请求（后端有幂等分支兜底） |
| 8 | `code === "0000"` 硬编码 | 两个页面 | 🟡 低 | 魔法值散落，建议统一常量 |

## 8. 改进版代码

### 8.1 login.html 关键片段

```javascript
const API = '/api';                       // 走 Nginx 同源反代
const MAX_POLL = 100;                     // 最多轮询 100 次（约 5 分钟）

async function initLogin() {
    const res = await fetch(`${API}/v1/login/weixin_qrcode_ticket`).then(r => r.json());
    if (res.code !== '0000') return;

    const ticket = res.data;
    document.getElementById('qr-code-img').src =
        `https://mp.weixin.qq.com/cgi-bin/showqrcode?ticket=${ticket}`;

    let count = 0;
    const timer = setInterval(async () => {
        if (++count > MAX_POLL) {           // 超时退出
            clearInterval(timer);
            alert('二维码已过期，请刷新页面');
            return;
        }
        const r = await fetch(`${API}/v1/login/check_login?ticket=${ticket}`).then(r => r.json());
        if (r.code === '0000') {
            clearInterval(timer);
            window.location.href = 'index.html';   // 登录态由后端 Set-Cookie 下发
        }
    }, 3000);
}

document.addEventListener('DOMContentLoaded', initLogin);
```

**改动点**：相对路径、轮询上限、不再由前端写 openid Cookie。

### 8.2 index.html 关键片段

```javascript
let submitting = false;

document.getElementById('orderButton').addEventListener('click', async function () {
    if (submitting) return;               // 防重复点击
    submitting = true;
    this.disabled = true;

    try {
        const res = await fetch(`${API}/v1/alipay/create_pay_order`, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ productId: '100010090091' })   // 不再传 userId
        }).then(r => r.json());

        if (res.code !== '0000') {
            console.error('下单失败', res.info);
            return;
        }

        const container = document.getElementById('pay-container');
        container.innerHTML = res.data;
        const form = container.querySelector('form');
        if (form) form.submit();          // 精确提交目标表单
    } finally {
        submitting = false;
        this.disabled = false;
    }
});
```

**改动点**：不传 userId、精确查表单、防重复点击、失败可恢复。
